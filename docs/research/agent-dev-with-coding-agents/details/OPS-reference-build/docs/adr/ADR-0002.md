# ADR-0002: post_ledger_entry 走 ask/deny + PreToolUse 硬阻断

**状态**: 已采纳

**决策**: `post_ledger_entry` 工具的写库操作分两层保护:
1. `.claude/settings.json` permissions:deny `Bash(rm:*)` / `Bash(sqlite3:*)` / `Write(**/ledger.db)` / `Edit(**/ledger.db)`;ask `mcp__expense__expense_post_ledger_entry`。
2. PreToolUse hook 链(两道,均已在 settings.json 注册):
   - `.claude/hooks/pre_tool_use_guard.sh`:第一道,matcher=`Edit|Write|MultiEdit|NotebookEdit|Bash`,拦截通用危险写操作。
   - `.claude/hooks/guard_ledger.py`:第二道,matcher=`Bash`,专门命中 ledger.db / post_ledger 写操作时 `sys.exit(2)` 阻断(exit 2 = 阻断;exit 1 = 不阻断,不要混淆)。

**理由**: 写 `ledger.db` 是不可逆副作用。散文规则只是指引不是强制层。真正的拦截必须在 harness 层:settings.json 的 permissions + hook exit 2。人审是最后一道门。

**拦截边界**: settings.json + guard hooks 只覆盖「Claude Code 开发期跑 shell 碰 ledger.db」。运行时 `src/agent.py` 经 SDK 调 `post_ledger_entry` 时 Bash hook 拦不到,运行时人审要在 agent 代码的 manual tool loop 里自建。

**改变此决策前须**: 更新本 ADR + 同步改 settings.json + guard hooks + 人审。
