# ADR-0003: eval 用 code-based grader + pass^k,贯穿开发

**状态**: 已采纳

**决策**:
- 抽取字段(vendor/date/amount/currency/amount_base)用 code-based grader(精确比对 + 数值容差),不用 LLM 当裁判。
- 分类一致性(category)用 pass^k(k=5,全部命中同一类才过)。
- eval 贯穿开发:改 src/ 前先在 evals/cases/ 加/改 case,改 prompt/工具时同步跑 grader。不是「写完再补测试」,不是「动手前先建完整 eval」。

**理由**: 抽取字段有确定的对错,用 LLM 裁判会引入 agent 自我打分的风险(reward hacking)并破坏 evaluator 隔离。pass^k 对分类一致性比 pass@k 更严格:同一输入 k 次必须全部一致,而不是「至少一次对」。贯穿开发确保 eval 是发现问题的工具而不是验收的仪式。

**注意**: `gather → act → verify` 是 agent 运行时循环,不是 eval 开发步骤。

**改变此决策前须**: 更新本 ADR + 同步改 evals/config.yaml + 经人审。
